# 模型连接与规则理解验收

适用 DSH、Codex、Claude 或其他能够执行客户端/HTTP 请求的宿主，不依赖 QQ 或微信。不要求额外模型 API：当前宿主可以负责理解规则、上下文及图片。后台视觉 API 只是无人值守批量标注的可选方式。

1. 调用 client.mjs state 和 contract，成功读取版本、设置、词表、规则。仅此只能报告“服务连接通过”，不能声称模型已理解。
2. 当前模型读取 contract.rules，解释意图以发送者为准、抽象放宽、avoid、对象方向、成功才计入历史。不要只复述标签名称。
3. 模型自己分析下列原始对话，构造 delivery/select 参数并实际调用。session 使用独立 test:model 标识，turn 每个用例独立；不调用发送工具，不提交 sent 回执。不读取完整图库，候选最多 6 张。
4. 阅读候选具体文案与含义，给出所选图片编号和一句理由，或者如实说明库存不足。返回候选不代表语义合格；不能把无合适图片算作模型无法连接。

| 原始对话 | 验收标准 |
| --- | --- |
| 用户：谢谢你，帮大忙了 | 助手表达不客气/回应，不能机械等同用户感谢 |
| 用户：能不能少花我点 token 哈哈 | 可识别调侃，不调用设置接口降低频率 |
| 用户单独发“发呆”表情 | 有视觉能力时先理解图片，可纯图回应，不解释用户发了什么 |
| 用户：家人生病了，我很害怕 | 安慰、真实痛苦/严肃健康，不发幸灾乐祸图 |
| 用户：以后别自动发表情 | 识别明确修改配置；验收模式只报告拟修改项，不改变真实设置 |
| 用户：终于忙完了，今晚摆烂！ | 可庆祝/共鸣，允许相近和抽象，结合具体图文判断 |

输出简表：服务连接、规则理解用例、候选语义匹配、图片读取能力分别列出通过/失败/未测及依据。图片能力需要实际读取一张已授权本地图片才能判定，不从“已配置”推断可用。不改变用户图库或配置，不发送消息。若宿主不支持图像，文字规则和已标注候选仍可用，但新图语义标注未通过。
