# 发送规则与语义选图

## 一轮如何执行

1. 理解最近对话、用户语气及准备发送的文字回复，判断**助手想表达什么**。用户“谢谢”通常配“不客气”的回应；用户累了要安慰或共鸣，不能机械搜索“累”发“我不想理你”。调侃不等于改设置，只有明确的配置请求才调用 delivery/settings。
2. 向 delivery/select 传下面的结构。session 使用包含渠道和接收者的稳定标识，turn 使用当前用户消息的稳定编号；同一轮重试必须相同。不要把完整聊天记录写入请求，只传语义标签。
3. 返回最多 6 张候选。阅读每张 text、meaning、when、target、avoid，选最符合**即将发出的回复**的图。标签负责召回，具体含义作最终判断；标签一样也可能文案相反。无需每轮重新让视觉模型看已标注图片。
4. 发送前通过服务 image 接口或宿主文件工具核对所选 path 对应图片仍存在、内容未变化。调用宿主原生图片发送工具，发到当前授权会话。通常正文后发一张；用户只发表情时可以只回表情，不解释“你发了一个……”。用户其实在求助或图片是文档/照片时，优先处理真实需求。
5. 根据宿主工具的实际结果提交 receipt。成功有消息编号才填 sent；明确失败填 failed；超时或结果不明确填 unknown，先查渠道发送记录，不盲目补发。无图适用填 skipped。无发送工具只返回可展示的本地图片/路径，并说明尚未发送，不填 sent。

## 请求

```json
{"session":"platform:recipient-id","turn":"incoming-message-id","intents":["安慰","共鸣"],"emotions":["担心"],"styles":["温柔","可爱"],"scenes":["工作"],"target":"对方","intensity":1,"avoid":[],"requested":false,"memeOnly":false,"playful":false,"natural":true}
```

- 标签来自 schema.vocabulary；target 指助手表达的对象，不是图中角色的朝向。
- avoid 指当前情境需要规避的风险，必须结合语义判断，不靠关键词触发。例如“笑死了”不等于真实痛苦。
- playful：当前是否允许抽象、玩笑联想。轻松互动可为 true；真实痛苦、严肃事务为 false。
- natural：在自然频率下，这轮是否适合配图；明确要表情或用户只发表情不依赖此值。
- requested：用户本轮明确要求图片，不用每轮重复询问许可。

## 排序与放宽

优先：同意图 → 相近表达 → 轻松情境下抽象联想 → 温和通用表达。情绪、风格、场景、强度共同排序，不要求全部标签一致。不按来源偏袒自带图、旧图或小红书图。

- 同意图基础 60 分、相近 40、抽象 25、温和通用 15；情绪 +12、风格 +8、场景 +6；强度每差一级 -4。
- 最近成功发送的图片最多降 35 分，逐渐减弱；不是永久禁用，也没有连续三次后强制停发。
- 文件删除/断开图库、未完成理解、不可用、明确场景冲突的图不参选。表达对象错误也不选。
- 每轮模式尽量一张，不能为凑数发反话、侮辱或与回复相反的图。库存不足可返回无合适图片，不实时爬网阻塞聊天。
- 相近和抽象只表示候选，不证明含义正确。比如“哈哈哈”可以接玩笑，但不适合用户真实受伤；“不想理你”不能接认真求助。认真场景可选温和安慰，不必完全禁用图片。

## 回执

```json
{"session":"platform:recipient-id","turn":"incoming-message-id","deliveryId":"select返回值","imageId":"所选id","status":"sent","messageId":"宿主发送返回的消息编号"}
```

频率设置：`delivery/settings` 接受 enabled、frequency（every/natural/requested）、style（跟随聊天或词表风格）、avoidRepeat。关闭后不自动选图；用户要求恢复才重新开启。

同一轮 sent/unknown 后不会再次选图，unknown 需要人工/渠道核验，禁止换 turn 绕过。pending 有效 10 分钟；仅明确 failed 且渠道确认未发送时最多补发一次。不同接收者分别记录，不复用候选回执。回执保留 30 天，只存图片编号和消息编号，不存原始聊天。

## 情境示例

| 对话 | 助手表达 | 选图要点 |
| --- | --- | --- |
| 谢谢你 | 回应、亲切 | 不客气，比心回礼；不要再次道谢造成错位 |
| 今天累死了（笑） | 共鸣、调侃 | 累瘫或打工抽象图可用，不直接推断严重痛苦 |
| 能不能少花我点 token（笑） | 调侃、自嘲 | 可回装乖，不改频率、不改预算 |
| 单发表情“发呆” | 共鸣、表达状态 | 可回发呆或一起摆烂，通常纯图片 |
| 终于交完了 | 庆祝、赞赏 | 开心或夸赞，优先适中强度 |
| 家人生病，我很害怕 | 安慰 | 温和陪伴，不用幸灾乐祸或抽象戏谑 |
| 帮我整理计划 | 回应、鼓励 | 收到/开工，不用“懒得干”的反向文案 |
| 以后不要发表情 | 配置变更 | 关闭并确认，此轮不再补图 |

## 宿主接入（平台无关）

DSH、Codex、Claude 等负责实际调用：在该用户授权启用的聊天回合完成钩子里传入上下文标签，取得候选后选图并发送，再记回执。控制台不能凭空取得这些软件的会话和发送权限。不要为了开启本功能改动所有会话的系统提示或私自安装渠道插件；只对用户要求接入的会话配置。

验收本 Skill 只需模型连接、读取规则并完成选图用例，见 model-check.md；不以 QQ、微信或任何渠道的发送成功作为 Skill 适配前提。实际图片展示/发送能力由宿主决定。
